# Remen Okoruwa

Leading marketing at [Propexo](https://propexo.com) taught me to treat AI output like a pull request, reviewed before it merges.

## What I've built

- **Governance first.** AI drafts in my name drifted off voice and made up numbers. Each external draft now clears my voice rules and a pre-publish taste gate, then waits for my sign-off. Any number without a source prints as TBD. Outcome: TBD.
- **A merge gate for process changes.** Runbooks and skills used to merge on their author's own read. A cold critic subagent now reviews each change, and a separate verifier re-checks the fixes before merge. Outcome: TBD.
- **One shared context layer.** Each skill kept re-explaining the ICP and the voice. A foundation layer now holds them once, and 34 active skills load what they need from it. Outcome: TBD.
- **Scheduled jobs with tests.** Recurring work like lead alerts and metric reports lived in people's heads. The job library now holds 40 active job specs and 137 test files, and every run posts a health line. Outcome: TBD.
- **AEO.** Buyers started asking chat assistants which vendor to pick. A monthly answer-engine research pass and a site audit job now feed fixes through a human review loop. Outcome: AEO-attributed leads went from 2 a month in June 2026 to 4 a month in October 2026.

## Open source

Built one at a time from fresh files. Only gtm-os-starter is live so far.

- **[gtm-os-starter](https://github.com/rokoruwa/gtm-os-starter)**. A forkable skills and context layer, set up for a fictional company called Northwind Rentals.
- **ai-output-gates** (not live). The review gates that stop AI drafts and process changes before they ship.
- **gtm-agent-fleet** (not live). Scheduled GTM jobs with tests, health lines and a heartbeat.
- **case-studies** (not live). Write-ups of what worked and what didn't.
